## What was implemented

### 1. Autonomous emergency SOS (direct SMS)
- Native `SmsManager` channel `com.sina.mobility/sms` (`MainActivity.kt`) — sends
  SMS directly, no taps, works without internet (cellular). `SEND_SMS` added to
  manifest; requested up front in `activate()`.
- `services/sms_service.dart` (new) — permission + send wrapper.
- `buildSosSms()` (FR/EN/AR) with `maps.google.com/?q=lat,lng`; spoken
  confirmations `msgSosSmsSent/Failed/NoContact` in `labels.dart`.
- `triggerSOS` reworked: SMS is primary; dialer/WhatsApp only as fallback on
  failure (so a successful SOS doesn't yank the user out of the app).

### 2. Auto-call after the text
- Native ACTION_CALL channel `com.sina.mobility/call` + `services/call_service.dart`.
- On a successful SOS text, rings the **first** contact when `autoCallOnSos`
  (default on). `CALL_PHONE` requested in `activate()`. `_placeCall()` falls back
  to the dialer / WhatsApp if the OS call can't be placed.

### 3. Recurring location check-in
- After an SOS, `_startLocationSharing()` runs a `Timer.periodic` every
  `sosCheckInMinutes` (1–10, default 2) asking "send a new location?"; **yes** →
  resend to all contacts, **stop/no** → end. SOS phrase always overrides.

### 4. Multiple emergency contacts
- `models/emergency_contact.dart` (new); `settings.emergencyContacts` stored as
  JSON, migrates the legacy single `familyPhone`. SOS texts **every** contact,
  calls the first.

### 5. Hands-free contact management (voice)
- Commands: **"my contacts"** (reads them aloud), **"add a contact"** (guided
  name → digit-by-digit number → spoken read-back → confirm → save), **"delete
  contacts"** (confirm → clear).
- New `commands.dart` helpers: contact intent branch (`_contactWords/_addWords/
  _removeWords`), `parseSpokenDigits` (numerals + FR/EN/AR digit words),
  `isAffirmative/isNegative/isCancel`.
- Controller dialog state machine `_DialogStep {resendConfirm, addName, addPhone,
  addConfirm, clearConfirm}` driving `_handleDialog`.

### 6. SOS confirmation guard (false-alarm prevention)
- Setting `confirmSos` (default on). `triggerSOS` → `_beginSosConfirm()`:
  full-screen red **tap-anywhere overlay** + **voiced 10→1 countdown**. Tap
  (`confirmSosNow`) → `_sendSos()`; no tap → cancel + resume listening. Detection
  announcements + resend prompt suppressed during the countdown.
- Overlay in `screens/main_screen.dart` (`_sosConfirmOverlay`).

### 7. First-run onboarding
- `screens/onboarding_screen.dart` (new): shown when `!firstRunDone &&
  emergencyContacts.isEmpty`. Speaks a welcome, shows the contact editor, Continue
  only proceeds once ≥1 number is saved; sets `firstRunDone`. Routed from
  `main.dart` via a conditional `initialRoute`.
- Extracted shared `widgets/contacts_editor.dart`, used by **both** onboarding and
  settings (settings refactored to drop its inline editor).

### 8. Earlier-found fixes (carried in)
- **Voice-command collisions** rewritten in `commands.dart`: direction-aware
  toggles so "stop GPS" → `gps_off` (was `camera_off`), "lower volume" →
  `volume_down`; `help`/`sos` overlap resolved (SOS keeps "help"/"aide").
- **`describeScene`** now recomputes from the live frame's boxes, not the last
  enqueued (possibly stale) announcement.

## Key decisions & caveats
- **Direct SMS** chosen as the autonomous SOS channel (hands-free, offline,
  free-in-plan). `SEND_SMS`/`CALL_PHONE` are Play-Store-restricted — fine for a
  side-loaded PFE APK, would need a policy declaration for Play distribution.
- Auto-call backgrounds the app (call UI) until the call ends — accepted for an
  emergency; the check-in timer keeps running while the process is alive.
- Distance is bbox-area based → meaningless for ground-plane classes
  (curb/crosswalk); treat those as presence alerts unless ARCore depth is wired.

## ⚠️ Gotcha for the custom model
- Traffic-light colour code **hardcodes class index 9** in
  `detector_service.dart:274` and `app_controller.dart:459`. A custom model with a
  different class order must either keep traffic light at index 9 or update those
  two lines (suggested: a `kTrafficLightClassId` constant in `yolo_config.dart`).
