  YUV→RGB; nested-List model input; **no delegates**; per-frame full-screen
  rebuilds; float32 model.

  spoken sentences for danger (slow); no spatial audio; fights TalkBack; missing
  hazard classes (no **bus/truck**); low-contrast tiny buttons; SOS hard to find
  non-visually; STT 3 s end-pause; dies when backgrounded.
- **Correctness:** **COCO label swap** (58/60); aspect-ratio distortion from
  stretch-resize; `usesCleartextTraffic` unnecessary.

### Notable implementation details
- **Detector** (`detector_service.dart`): full pipeline (YUV→RGB → letterbox 320 →
  `Float32List` → `interpreter.run` → decode → NMS → traffic-light colour) runs in
  a long-lived **worker isolate**; decode is now **class-count-agnostic** (numClasses
  derived from output shape), so a custom model drops in without code changes.
- **Spatial audio**: `beep.wav` (880 Hz, 130 ms) panned by direction, pitched by
  distance via playback rate.
- **OCR**: ML Kit Latin script; `takePicture()` (pauses stream) → recognize → speak.
  No Arabic script model in the plugin (FR/EN only).
- **Foreground service**: native Kotlin, FGS types camera|location|microphone,
  started/stopped with the camera; `START_NOT_STICKY`.
- **Battery throttle**: inference gap 120 ms → 220 ms (≤30%) → 400 ms (≤15%/saver).
- **Depth seam**: `DepthService` (MethodChannel `com.sina.mobility/depth`),
  `RawBox.distanceMeters`, `distanceTierFromMeters()`, fallback to area heuristic.
  Native stub returns unavailable; full ARCore guide in `docs/arcore_depth.md`.
- **Volume-key SOS**: triple-press volume-down within 1.5 s (native, passes key
  through); also long-press anywhere on the home screen.

## Key decisions & caveats
- Chose **float16** over int8 for the model (keeps float32 I/O → decoder unchanged);
  int8 needs added dequant in the decoder.
- ARCore depth delivered as **Dart seam + guide**, not committed native code,
  because an ARCore session owns the camera (replaces `package:camera`) and is
  untestable without a device.
- Traffic-light state is a **colour heuristic**, not a trained classifier — it
  prefers silence when unsure; thresholds need on-device tuning.
- Did **not** add `liveRegion` to spoken UI text (would make TalkBack double-speak
  what SINA's TTS already says); used `ExcludeSemantics` instead.

## Device-testing fixes (same day, after first on-phone test)

Built and ran the release APK on a real phone; fixed three field issues:

1. **Wrong APK installed** — an old 81 MB build lived in a separate
   `PFE-mobile_app_v0/` folder; today's build is in `PFE-mobile_app_v1/` and is
   ~112 MB. (Sort by date / check size to pick the right one.)
2. **Camera showed nothing** — `ExcludeSemantics` had been wrapped *around*
   `CameraView`, whose root is a `Positioned`; a `Positioned` must be a direct
   child of its `Stack`, so the layout broke in release. Moved the exclusion
   *inside* `CameraView`. Also **removed the tap-to-activate overlay** and made
   the app **auto-activate on launch** (post-frame `activate()`).
3. **App crashed when opening the camera** — the native foreground service
   started with `location|microphone` FGS types, which Android 14 rejects with a
   `SecurityException` when those runtime permissions aren't granted (location
   isn't, by default). Changed to **camera-only** type (always granted at
   detection time) + try/catch `stopSelf()`. Also set **`kUseGpuDelegate = false`**
   (CPU/XNNPACK) since the GPU delegate can hard-crash on some devices.
