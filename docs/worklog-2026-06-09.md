## What was verified

- Shipped `assets/models/yolov8n.tflite` (~6 MB float16). Inspected with
  `ai_edge_litert`: input `[1,320,320,3]` float32, output **`[1,28,2100]`**
  float32 → 4 bbox + **24 classes**. So the OOD custom navigation model was
  trained and dropped in (the 06-07/06-08 worklogs predate this — they describe
  the model as "still to train").
- Decoder is class-count-agnostic: `outShape[1] < outShape[2]` → features-major,
  `numClasses = 28-4 = 24`. Decodes the custom model correctly with no code
  change. `cocoLabels` (0–23) + `targetClassIds` ({0..23}) + `labels.dart`
  (all 24) line up. Traffic light = index 16 in all three places.
- `flutter analyze lib test` → **No issues found**.
- `flutter test` → **7 pass, 1 fail** (the stale COCO assertion).

## Findings (prioritized)

### HIGH

**H1 — Model regeneration is a silent-corruption trap (docs + script stale).**
The runtime is correct, but every documented way to *rebuild* the model is
wrong for the shipped 24-class model:
- `sina_mobile/assets/models/README.md` — says output `[1,84,2100]` / 80 COCO
  classes; tells you to run `scripts/export_tflite.py`.
- `scripts/export_tflite.py` — exports from `yolov8n.pt` (COCO). Dropping that
  in keeps the app running (agnostic decoder) but mislabels everything: COCO
  class 0 (person) → announced "bench", class 2 (car) → "bus", etc., and most
  real hazards filtered out by `targetClassIds`. Silent and safety-relevant.
- `CLAUDE.md` detection section still describes COCO IDs, `[1,84,2100]`,
  "traffic light class 9", "COCO label swap 58/60 being fixed", bus/truck "being
  added" — all superseded.
- Fix: update README + CLAUDE.md to the 24-class reality; repoint or remove
  `export_tflite.py` (note the custom weights are **not** in the repo —
  `runs/detect/train*/weights` are empty), and document that the model is
  produced by `scripts/sina_custom_model_colab.ipynb` from the OOD dataset.

**H2 — Test suite is red; assertions are for the old COCO model.**
`test/widget_test.dart`:
- `cocoLabels[58]` expected `'potted plant'` → now `null` (FAILS).
- comments claim class 5 = bus, 7 = truck → now 5 = crutch, 7 = dog (pass by
  luck because both indices are in `targetClassIds`, but the test no longer
  tests what it claims).
- Fix: assert the real 24-class invariants, e.g. `cocoLabels[16] ==
  'traffic light'`, `kTrafficLightClassId == 16`, label/ID count agreement,
  every `targetClassIds` entry has a `cocoLabels` + `labels.dart` entry.

**H3 — SOS confirmation fails unsafe + is tap-only on a voice app.**
`confirmSos` defaults ON. `triggerSOS → _beginSosConfirm`:
- 10s voiced countdown; **a tap sends, no tap cancels**. An incapacitated /
  panicking blind user who cannot tap loses the alert after 10s. For an
  emergency tool the safe inversion is *send by default, tap/voice to cancel*.
- `_beginSosConfirm` does `await _stt.cancel()` and never re-listens, so the
  alert **cannot be confirmed by voice** — only `confirmSosNow()` via the
  overlay's `GestureDetector` resolves it. Mitigant: the overlay is full-screen
  opaque, so *any* tap works (no aiming). Still, the most critical action in a
  voice-first accessibility app is visual-tap only.
- Recommend: (a) accept a spoken "yes/send" during the countdown, and/or
  (b) flip the default to send-and-allow-cancel, and/or (c) make the
  tap-to-confirm explicitly opt-in rather than default-on.

### MEDIUM

**M1 — Resend check-in can stall location sharing.** `_promptResendLocation`
sets `_dialog = resendConfirm`; if the user never gives a yes/no, the periodic
timer keeps firing but early-returns on `_dialog != none`, so check-ins stop
while `_locationSharingActive` stays true. Add a dialog timeout that reverts to
`none` (or re-prompts).

**M2 — Resend dialog can be hijacked by an unrelated command.** In
`_handleDialog` (resendConfirm), a non-yes/no transcript falls through to
`_handle(text)`, so e.g. "settings" mid-emergency navigates away. Consider
re-prompting instead of dispatching during an active SOS check-in.

**M3 — Manifest declares unused FGS permissions.**
`FOREGROUND_SERVICE_LOCATION` and `FOREGROUND_SERVICE_MICROPHONE` are declared
but the service only starts with `FOREGROUND_SERVICE_TYPE_CAMERA` (deliberate,
to avoid the Android 14 crash). Dead permissions; location FGS in particular
invites Play Console policy review. Remove both.

**M4 — Per-pixel pure-Dart YUV→RGB is the per-frame bottleneck.**
`_yuv420ToImage` loops every pixel with `setPixelRgb`, then the input-fill loop
calls `getPixel` per pixel. On a Snapdragon-400 target this dominates frame
cost even on the worker isolate, capping real FPS. Roadmap (not a regression);
options: convert during/after a downscale, or a typed RGB buffer instead of the
`image` package per-pixel API.

### LOW / DOCS

- **L1** `CLAUDE.md` header "Last Updated June 7" + detection section is stale
  (see H1). Note the `kTrafficLightClassId` refactor is now done.
- **L2** `models/detection.dart` — `RawBox.lightState` doc says "for classId 9";
  now index 16 via `kTrafficLightClassId`.
- **L3** `assets/models/README.md` "Expected tensor shapes" wrong (84 → 28).
- **L4** Empty `runs/detect/train*/weights` and `dataset/` (no `data.yaml`,
  empty `models/`) — training artifacts were cleaned but the custom weights/
  dataset are not in the repo, so the model can't be reproduced locally. Worth a
  note in the README (Colab is the source of truth).

3. H3 (SOS confirm safety/voice — design decision needed).
4. M1–M3 (small correctness/policy fixes), then M4 (perf, roadmap).
